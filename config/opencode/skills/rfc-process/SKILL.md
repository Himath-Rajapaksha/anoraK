# RFC Process

## When to Use This Skill
- Proposing a new architecture, feature, or process change
- Structuring a proposal with context, alternatives, and recommendation
- Facilitating team review and building consensus
- Documenting the decision and rationale for future reference

## Workflow
1. Define the problem: what needs to change and why
2. Write the RFC: background, proposed solution, alternatives considered, and recommendation
3. Share for review: give the team time to read and comment
4. Facilitate discussion: address questions and incorporate feedback
5. Make the decision: record the outcome and rationale
6. Document the decision: store the RFC with the final decision
7. Implement: follow the approved proposal and reference the RFC

## Rules
- Write the RFC before starting implementation
- Include at least two alternatives with pros and cons
- State assumptions and constraints explicitly
- Give reviewers at least one week for non-urgent RFCs
- Record the decision, including dissenting opinions
- Reference the RFC in commits and PRs during implementation
