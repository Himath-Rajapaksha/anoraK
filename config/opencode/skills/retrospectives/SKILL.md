# Retrospectives

## When to Use This Skill
- Facilitating a team retrospective after a sprint or project
- Identifying actionable improvements from team feedback
- Tracking follow-through on previous action items
- Building a culture of continuous improvement

## Workflow
1. Set the stage: state the purpose and create a safe space for honesty
2. Gather data: what went well, what didn't, what could improve
3. Generate insights: discuss root causes, not just symptoms
4. Decide on improvements: pick 1-3 actionable items
5. Assign owners and deadlines for each action item
6. Track progress: review previous action items at the start of each retro
7. Follow up: check if actions were completed and had the intended effect

## Rules
- Focus on systems and processes, not individuals
- Limit action items to 1-3 per retrospective — don't overload
- Every action item needs an owner and a deadline
- Review previous action items at the start of every retro
- Keep the retrospective time-boxed — 60-90 minutes maximum
- Follow up on actions — missing follow-through kills team trust
