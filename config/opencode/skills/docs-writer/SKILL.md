# docs-writer

Writes and maintains clear, comprehensive project documentation.

## When to Use

Use this skill when:
- The user asks to write or update documentation
- New features need documentation
- README needs updating
- API docs need to be generated or maintained

## Documentation Types

### README.md
- Project overview and purpose
- Quick start / installation
- Usage examples
- Configuration options
- Contributing guidelines

### API Documentation
- Endpoint/method signatures
- Request/response examples
- Error codes and handling
- Rate limiting info

### Code Documentation
- Module-level purpose statements
- Complex algorithm explanations
- Non-obvious design decisions
- Examples for public APIs

### Configuration Docs
- All available options with defaults
- Environment variable references
- Example configurations

## Writing Style

- Use clear, concise language
- Include code examples for every concept
- Use consistent formatting (headers, lists, tables)
- Write for the audience (beginner vs expert)
- Keep docs close to the code they describe

## Rules

- NEVER leave placeholder documentation
- ALWAYS include working code examples
- Update docs when code changes
- Use markdown formatting consistently
- Document both what and why
