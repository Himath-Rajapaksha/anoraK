# Discovery Process

## When to Use This Skill
- Starting a new feature or project with unclear requirements
- Validating assumptions before committing to an approach
- Creating decision documents for architectural choices
- Handing off research to implementation teams

## Workflow
1. Define the question: what decision needs to be made
2. Gather requirements: interview stakeholders, review existing docs
3. Research options: technical feasibility, pros/cons, cost/effort
4. Validate assumptions: test key hypotheses with prototypes or data
5. Create a decision document: context, options, recommendation, and rationale
6. Review with stakeholders: get alignment on the direction
7. Hand off to implementation: provide the decision doc and acceptance criteria

## Rules
- Write the decision document before starting implementation
- Include at least two viable options in the analysis
- State assumptions explicitly — don't let them hide in the analysis
- Get stakeholder sign-off before proceeding to implementation
- Keep the document updated as new information emerges
- Reference sources for all technical claims
